一、总体概览

这是一个跑在 Electron 桌面端里的 A 股投资分析智能体。它以 @earendil-works/pi-agent-core 的 Agent 为「大脑」（负责 LLM 流式调用、 工具编排、上下文管理），以 @earendil-works/pi-ai 为模型/流式底座， 外面包了一层自己写的「投资专用骨架」——把真实数据源（东方财富、Tushare）、确定性因子计算与回测、 运行时 Skill 技能包、会话持久化、计划-执行-校验循环，全部接到这个大脑上。

核心设计原则只有三条：

  • 确定性能力下沉给代码，不交给 LLM 算：K 线指标、因子信号、回测、PDF 下载/解析都是 TS 代码，LLM 只负责「决定调用哪个工具、传什么参数、如何解读结果」。
  • 短系统提示 + 渐进披露：主 system prompt 只有十几行；细节知识装进运行时 Skill，按需通过 use_skill 注入，压缩/切上下文时也不怕丢。
  • 可恢复的循环：意图记在 task.md、步骤光标记在 todo.md，两者都落盘，即使上下文被压缩也能用 read_todo 恢复进度。

五、模块细节

5.1 ESM 懒加载（pi.ts）

本项目主进程是 CommonJS，而 pi 系列包是 ESM-only， 不能直接 require。因此用动态 import() 懒加载并缓存， 所有用到 pi 的地方（agent.ts、tools/index.ts）都先 await loadPi()。 

// pi.ts —— ESM-only 包在 CJS 主进程里只能动态 import
export async function loadPi() {
  if (!ai)  ai  = await import('@earendil-works/pi-ai');
  if (!core) core = await import('@earendil-works/pi-agent-core');
  return { ai, core };
}

5.2 Model 构建（models.ts）

buildModel(config) 把用户在设置里填的 provider/model/apiKey 映射成 pi-ai 的 Model 对象。关键点：deepseek 与 custom 都走 OpenAI 兼容协议 （api:'openai-completions'），openai 走官方 v1 接口，anthropic 走 anthropic-messages。每个 Model 都声明 contextWindow（deepseek/openai/custom 128k， anthropic 200k），这是后面上下文压缩判断窗口上限的依据。

5.3 Agent 核心（agent.ts）

这是整个系统的枢纽，负责四件事：单例化 Agent、订阅事件并翻译成 UI 事件、注入运行时配置、注册 IPC。

原子化单例

曾经有个卡死 bug：首次打开或点击历史记录时，if (!agent) 之后连续多个 await， 并发调用会各建一个 Agent、各订阅一次，导致重复订阅卡死。现在用「在途 Promise」原子化： 

let agentPromise: Promise<AgentInstance> | null = null;
async function ensureAgent() {
  if (agent) return agent;
  if (!agentPromise) {
    agentPromise = createAgent().catch(err => { agentPromise = null; throw err; });
  }
  return agentPromise;
}

创建 Agent 与订阅

const a = new core.Agent({
  initialState: { systemPrompt, model, tools },
  streamFn: ai.streamSimple,       // 流式底座
  toolExecution: 'parallel',       // 工具并行执行
});

// 上下文压缩兜底：接近窗口上限时压缩早期历史（见 5.9）
a.transformContext = (messages, signal) => compactContext(messages, {...});

// 把 Agent 内部事件翻译成发给 UI 的 AgentEvent
a.subscribe(async (event) => {
  switch (event.type) {
    case 'agent_start':  emit({type:'run_start'}); break;
    case 'message_update': /* text_delta / thinking_delta → 逐字 */ break;
    case 'tool_execution_start': emit({type:'tool_start', ...}); break;
    case 'tool_execution_end':   emit({type:'tool_end', ...}); break;
    case 'agent_end': await persistCurrentSession(); emit({type:'run_end'}); break;
  }
});

applySkill（技能注入）

use_skill 工具（自动路由）和 payload.skill（手动路由）共用 applySkill(name)：加载 SKILL.md 全文，拼到主 prompt 后面一个独立段，并持久化到 meta.currentSkill、推送 skill_applied 事件。切 skill 只替换这一段，主 prompt 保持短。 

function buildSystemPromptWithSkill(markdown: string): string {
  return `${SYSTEM_PROMPT}\n\n## 当前技能（skill）\n\n${markdown}`;
}

5.4 工具层（tools/）

每个工具一个文件，导出 createXxxTool(Type, ...deps)，返回 AgentTool { name, label, description, parameters, execute }。 parameters 用 TypeBox 的 Type 声明 JSON Schema（给 LLM 看参数约束）， execute 是真正跑代码的地方。所有工具统一由 createTools(ctx) 组装， ctx 注入两样运行时依赖：

  • emit(event) —— 把工具产出（todo_update/decision_update/file_saved）推给 UI；
  • applySkill(name) —— 供 use_skill 工具调用。

工具结果约定：execute 返回 ok(text, details)，ok() 把它包成 { content:[{type:'text', text}], details }——text 是给 LLM 读的摘要， details 是结构化数据（如信号列表）。以因子工具为例：

execute: async (_id, p) => {
  const def = FACTORS[args.factor];
  if (!def) throw new Error(`未知因子 ${args.factor}`);
  const { rows } = await getKlines(args.secid, args.period ?? 'day', args.limit ?? 250);
  const signals = def.fn(bars, args.params ?? {});
  return ok(
    { factor, buyCount, sellCount },   // text：LLM 看的摘要
    { factor, signals },               // details：完整结构化结果
  );
}

全套 21 个工具及分组见第十一节。

5.5 数据层（data/）

与外部世界打交道的地方，全部是确定性代码。核心 eastmoney.ts 封装东方财富公开接口， 字段已中文化（field-labels.ts 提供映射），返回给 LLM 前先「翻译」成中文键，减少 LLM 误读。 download.ts 负责 URL→Buffer（下载研报 PDF），files.ts 负责读文件 （PDF 用 pdfjs-dist 提文字、文本直读），indicators.ts 提供 MA/BOLL 等纯计算。 tushare.ts 是可选的补充数据通道（带 token 才启用）。

研报 PDF 是最近加的能力，两段式：

  1. getReportPdfs(secid) 拉研报列表（年份/报告类型/意见类型/发布状态，published = PUBLISH_SITUATIONS 以 'AN' 开头）；
  2. getReportPdfUrl(publishSituations) 用 art_code 换 PDF 直链 attach_url。

5.6 因子层（factors/）

因子是「确定性信号 + 确定性回测」的典型代表，LLM 只选因子、传参数，不参与计算。 index.ts 里每个因子是一个纯函数 fn(bars, params) → FactorSignal[]， 统一注册到 FACTORS：

因子说明参数（默认）
macd_crossMACD 金叉/死叉fast=12, slow=26, signal=9
ma_cross双均线金叉/死叉short=5, long=20
rsi_reversalRSI 超买超卖反转period=14, oversold=30, overbought=70
boll_breakout布林带突破period=20, mult=2

backtest.ts 的 evaluateSignals() 是事件驱动回测：每个 buy 信号买入， 到下一个 sell 信号（或持有 holdBars 根）卖出，输出 胜率、赔率（profit factor）、平均盈亏、逐笔明细。这保证「因子有没有效」是可复现的，而非 LLM 的主观判断。

5.7 Skill 层（skill/）

skill-registry.ts 扫描 resources/skills/ 下每个子目录的 SKILL.md， 用极简 frontmatter 解析只取 name/description/params 做索引（供 list_skills 与 UI 下拉），解析失败就跳过该 skill，绝不拖垮启动。 loadSkill(name) 再按需读回 SKILL.md 全文并缓存。 skill-paths.ts 处理 dev/prod 路径差异（dev 用仓库 resources/skills， prod 用 electron-builder extraResources 复制到 process.resourcesPath/skills）。

5.8 会话层（session/）

会话是「workspace 文件夹 + 其下一个隐藏目录」的自包含形态：

<workspace>/.ss-invst/sessions/<id>/
├── meta.json          # id/title/messageCount/updatedAt/currentSkill
├── messages.jsonl     # 消息追加写（每行一条 JSON）
├── task.md            # 目标 + 决策日志
├── todo.md            # 步骤光标（- [ ]/[~]/[x]）
├── uploads/           # 用户上传 + 下载的文件
├── files/             # save_file 默认产物
├── intermediate/      # skill 中间产物
└── output/            # skill 最终报告

saveSession() 是增量追加：只把 savedMessageCount 之后的新消息 append 进 jsonl（内存里 agent.state.messages 才是全量）。meta 用 writeJsonAtomic（先写 .tmp 再 rename）防止写一半损坏。 session-runtime.ts 只存三个内存态字段，供工具（save_file/read_file/run_script）取当前会话路径。

5.9 上下文压缩（compaction.ts）

这是「内存级压缩兜底」：只在上下文接近模型窗口上限时触发，不主动、不常驻。 关键设计是——只压缩喂给 LLM 的那份，磁盘历史全量保留。

  1. estimateContextTokens + shouldCompact 判断是否超预算（预留 4096 输出、保留最近约 12000 token）；
  2. findCutPoint 从后往前找最近的 user 消息作干净切点，不把一轮对话拦腰截断；
  3. 早期消息 generateSummary 压成一段投资定制摘要（重点保留股票代码/财务指标/结论/风险），拼成 [历史摘要, ...最近消息]；
  4. 摘要失败则退化为「直接截断保留最近」。
因为 task.md（意图+决策）和 todo.md（步骤光标）都在磁盘上， 即使早期对话被压成摘要，agent 也能用 read_todo / read_task 恢复进度—— 这正是「压缩可恢复」的底气所在。

5.10 系统提示（system-prompt.ts）

刻意保持极短，只有四块：工作方式（用 skill / 走循环）、报告要求、免责声明、循环骨架一行：

复杂多步任务循环：decide 记决策 → 执行 → 校验结果 → update_todo 推进 / 失败 refine 重试

循环本身由 pi-agent-core 提供，我们不重写，而是通过 subscribe 观察它、 通过 transformContext 在喂给 LLM 前拦截它、通过 getApiKey 供应凭据。 一次 a.prompt(text) 触发的内部节奏如下：

→

→
产出文本 / 工具调用

↺

对应的控制面（IPC 暴露给渲染进程）：

能力方法说明

七、计划-执行-校验循环

这是本项目的灵魂，对应你最初设想的 「skill → task → todo → decision → execute → lint → 循环」。当前实现是软循环： 由 system prompt + skill 约定驱动，靠 agent 自觉执行，不硬性拦截。 verify.js 字段已预留，未来「硬循环」会强制跑校验脚本。

循环靠两个落盘文件 + 三个工具实现：

task.md —— 意图不可变 + 决策日志

目标段可覆盖，决策日志只追加。关键选择用 decide(decision, reason?) 记下「为什么这么选」，压缩后也能恢复脉络。

todo.md —— 步骤光标

update_todo(todos) 整体重写 - [ ]/[~]/[x]， 标当前步/剩余步；上下文丢失时 read_todo 恢复。

decide
记决策到 task.md
→
执行
调用数据/因子工具
→
校验
接口空/非零退出/数据缺失？
OK
update_todo
推进下一步
Fail ↺
refine
read_todo 恢复 → 重试/换方案
软循环 vs 硬循环：软循环靠 prompt 约束，灵活但可能「自我宣布完成而不校验」； 硬循环会在每步后强制跑确定性校验（脚本非零退出 = 失败，自动 refine），由引擎拦截。 当前先落软循环，verify.js 作为硬循环的钩子保留。

八、事件系统

主进程把 Agent 内部事件翻译成一个 AgentEvent union，通过单一通道 agent:event 推给渲染进程。渲染进程只认这 14 种事件，不感知 pi 内部结构：

事件含义UI 表现
run_start / run_end一轮开始/结束停止按钮态
assistant_message_start/end助手消息气泡边界新建/收尾气泡
assistant_text_delta正文逐字增量Markdown 渲染 + 折叠工具
assistant_thinking_delta思考逐字增量折叠的思考区
tool_start/tool_update/tool_end工具生命周期工具卡片（展开/折叠、参数摘要）
todo_update任务清单变化「待办」标签页
decision_update新增决策「调试」标签页
skill_applied技能选定/清空当前技能徽标
file_saved保存/下载了文件对话底部文件卡片
errorLLM/工具错误错误气泡

九、运行时 Skill 系统（扩展机制）

这是把「某套投资流程」封装成可复用技能包的机制。分两层别混淆： 开发期 skill（.agents/skills/，给写这个 app 的编码 agent 用）与 运行时 skill（resources/skills/，给投资 agent 用）。 这里讲的是运行时这一层。

一个 skill 的目录结构

resources/skills/<name>/
├── SKILL.md        # 入口：frontmatter + 阶段大纲（保持短）
├── references/     # 按需 read_file 的知识（字段清单/检查表）
├── templates/      # report.md / report.html 模板
├── scripts/        # 可执行 Node 脚本（.mjs/.cjs，经 run_script 跑、不读源码）
└── verify.js       # 确定性验收脚本（预留，硬循环用）

frontmatter（决定路由）

---
name: value-investing
description: 长线价值投资分析……（含触发词，用于自动路由）
params:            # 可选，仅文档化
  - key: stock_code
    desc: 股票代码，如 600519
verify: verify.js  # 可选，预留
---

两种路由

  • 自动路由：LLM 根据 description 触发词自行 list_skills → use_skill；
  • 手动路由：用户在输入框左侧下拉选 skill，随 payload.skill 传进主进程。

use_skill 的效果是把 SKILL.md 全文注入 system prompt 的独立段（不是塞进消息历史）， 这样 compaction 不会把它截掉，且切 skill 只替换这一段。当前内置 4 个： value-investing、technical-signal、factor-research、financial-report-analysis。

十二、扩展点

想给 agent 加能力，三条路清晰分离：

加一个「流程」→ 写 skill

在 resources/skills/ 加目录 + SKILL.md（frontmatter + 阶段大纲）， 细节下沉 references/，可执行逻辑放 scripts/。自动被 list_skills 发现。

加一个「确定性计算」→ 加因子

在 factors/index.ts 的 FACTORS 里注册一个纯函数，即可被 compute_factor/analyze_factor 调用。

加一个「外部能力」→ 加工具

在 tools/ 写 createXxxTool(Type, ...deps)， 在 tools/index.ts 注册，必要时在 data/ 补数据函数。

加一个「硬校验」→ verify.js

skill 里放 verify.js，未来硬循环会强制跑它；现在先把验收标准写进 SKILL.md 正文。
